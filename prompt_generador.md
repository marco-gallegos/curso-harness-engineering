# Objetivo

crear un curso y/o roadmap sobre como iniciar en el harness engineering para profesionales (inteligencia e inferencia nivel bachelor degree es esperado y requerido) que no son tecnicos (TI, TIC, Electronica) si no mas bien administrativos (administradores, profesores, contadores etc).

## Consideraciones iniciales del perfil

### que no es esperado

- conocimiento de markdown
- saber programar
- experto en "computacion"
- uso de la terminal
- uso de sistemas unix como linux o mac
- uso de sistemas de control de versiones
- saber sobre mermaid


### que si es esperado

- sabe usar una computadora
- sabe usar ai chatbots para trabajar
- tiene computadora y acceso a internet.
- puede leer explicaciones detalladas.

## productos de salida

se espera que se genere una presentacion en slidev que sera exportada por el creador de esta presentacion (yo) en conjunto con archivos md que explican los punto requeridos de aprender en detalle, ejemplo:

- slide 1 a 5: hablan sobre markdown
  - deberia haber un archivo llamado markdown.md que describa que es, ejemplifique de forma sencilla y contenga referencias exteras para atender en detalle 

ademas debe generar un diagrama de flujo con temas y aprendizajes esperados para ir de 0 a eventualmente programar scripts sencillos y crear/conectar MCP servers.

### consideraciones para la presentacion

- ndebe estar escrita en markdown usando slidev
- debe ser facil de leer con archivos de detalles por cada tema.

### Consderaciones generales

- usa mermaid para diagramas
- solo usa markdown
- debe ser facil de leer
- el contenido debe ser minimo para empezar rapido conreferencias externas de mayor detalle (ej referencia complete del lenguaje markdown)

## puntos criticos de forma cronologica a tratar

- markdown: debe ser obligatorio y presentar estadisticas de por que es usado, ademas de un tutorial tipo cheat sheet
- antigravity: el agente en el que nos enfocaremos sin embargo m,encionar otros (esto es eleccion de negocio analizada por el humano implementador)
- slidev: por que se usa y a que formatos puede exportar
- mermaid: or que se usa y a que formatos puede exportar
- context engineering: explicacion de por que el contexto importa, AGENT.md, rules y el uso de tools (mencionar que hay existentes y pueden ser creadas), skills
- prompt engineering: explicacion basica para evitar prompts dummy

## Puntos no criticos (pero obligatorios eventualmente)

- control de versiones: git, github desktop, github y por que son necesarios
